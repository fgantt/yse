1. EVALUATION CALIBRATION ISSUES
────────────────────────────────────────────────────────────────────────────────

Issue: Arbitrary evaluation scaling (/ 256) breaks search integration
Location: src/evaluation/nnue.rs:314-320
  - Output scaling has NO JUSTIFICATION
  - Hidden layer 2 uses intermediate scaling: / 64
  - Cascading scale factors misaligned
  - Documented problem: docs/NNUE_SCALING_ISSUE.md (evolves / 16 → /400 → /256)

Impact:
  - Alpha-beta search assumes consistent evaluation scale
  - Aspiration windows (±50cp) become ineffective
  - Move ordering heuristics break
  - Time management miscalibrates position difficulty

Fix: Add tanh() activation + proper weight initialization
  Current: output / 256 (arbitrary)
  Needed: (output as f32 / 1000.0).tanh() * 200.0


2. TRAINING QUALITY ISSUES - TD(λ) BROKEN
────────────────────────────────────────────────────────────────────────────────

Issue A: Missing Eligibility Traces
Location: src/evaluation/nnue_training.rs:144-189 (compute_td_targets function)
  - Proper TD(λ) requires per-weight eligibility traces
  - Code has NO eligibility trace implementation
  - Just does linear blend: next_value = λ * next_value + (1-λ) * current

Issue B: Wrong TD Error Formula
Location: src/evaluation/nnue_training.rs:174-180
  - Missing discount factor γ (should be ~0.99)
  - Uses stale network output for current_value
  - Inconsistent tanh() conversion (/ 20000.0)
  - Formula: δ = r + γ*V(s') - V(s) but code has NO γ

Issue C: Incomplete Backpropagation
Location: src/evaluation/nnue_training.rs:232-333 (update_weights_for_position)
  - Output layer: gradient = error * (value / 64.0) [OK]
  - Input layer: gradient *= 0.01 [100x smaller, arbitrary]
  - Layer 2 to output: NEVER UPDATED
  - saturating_add() silently clamps weights to [-32768, 32767]

Issue D: No Regularization
Location: src/evaluation/nnue_training.rs (all of it)
  - No L1/L2 weight decay
  - No gradient clipping
  - No dropout or batch norm
  - Weights saturate → training stops


3. TARGET VALUE PROBLEM - BOOTSTRAP LOOP
────────────────────────────────────────────────────────────────────────────────

Issue: Training on NNUE play with NNUE evaluation (vicious cycle)
Location: src/bin/nnue_trainer.rs:253-273
  ```rust
  evaluator.enable_nnue_with_weights_internal(current_weights.clone());
  search_engine.get_evaluator_mut().enable_nnue_with_weights_internal(current_weights.clone());
  let game = play_self_play_game(&mut search_engine, &mut evaluator, &current_weights, &config);
  trainer.add_training_game(game);
  ```

The Problem:
  - Iteration 1: Random weights → garbage play → train on garbage
  - Iteration 2: Slightly-less-random weights → slightly-less-garbage → train
  - ...
  - Iteration 700: Locked-in biases, never learns real evaluation

Evidence:
  - Self-play depth: only 7 plies (very weak)
  - Time per move: 300ms (also weak)
  - No external oracle: No PST reference, no opening book, no tablebase

What Should Happen:
  - Self-play with STRONG evaluator (PST depth 10 or more)
  - Mix: 50% opening book, 25% search-generated, 25% self-play
  - Target value: game_outcome + search_depth_eval + tablebase_if_endgame


4. NETWORK ARCHITECTURE ISSUES
────────────────────────────────────────────────────────────────────────────────

Issue A: Second layer too small
Location: src/evaluation/nnue.rs:44-48
  - Architecture: 2268 → 256 → 32 → 1
  - First layer OK (256 neurons)
  - Second layer TOO SMALL (32 neurons, should be 512-1024)
  - Only 1 output (no hidden layer for combining features)

Issue B: No output activation
Location: src/evaluation/nnue.rs:308-312
  ```rust
  let mut output = weights.output_bias;
  for (i, &value) in final_values.iter().enumerate() {
      output += (value * weights.output_weights[i] as i32) / 64;
  }
  output / 256  // <- LINEAR OUTPUT, NO ACTIVATION
  ```
  - Should have tanh() to bound [-1, 1]
  - Currently unbounded, explains scale explosion

Issue C: ReLU dead neurons
Location: src/evaluation/nnue.rs:276-283
  - ReLU activation can lose information in dead neurons
  - Better: ELU, GELU, or swish for shogi eval
  - Shogi needs to model both positive and negative evals

Issue D: No layer normalization
Location: src/evaluation/nnue.rs (all layers)
  - No normalization between layers
  - Leads to internal covariate shift
  - Gradients may vanish/explode


5. WEIGHT INITIALIZATION ISSUES
────────────────────────────────────────────────────────────────────────────────

Issue: Weights initialized way too large
Location: src/evaluation/nnue.rs:84-119
  - Input weights: [-128, 128] (HUGE)
  - Biases: [-1000, 1000] (HUGE)
  - Proper initialization: weights ≈ ±√(2/fan_in) ≈ ±0.03
  - Proper initialization: biases = 0 or N(0, 0.1)

Impact:
  - First forward pass naturally saturates i16 range
  - Network immediately at worst case
  - Vanishing/exploding gradients from start
  - Training uphill battle
